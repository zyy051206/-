# 部署到 Cloudflare Pages

`public/` 是唯一需要上传的目录，它由 `deploy/build.py` 生成。站点本身没有构建步骤——纯 HTML/CSS/JS，Cloudflare 直接托管即可。

---

## 一、改完内容后先重新生成

```bash
python deploy/build.py
```

它会重建 `public/`，自动排除 `.git`、`deploy/`、`README.md` 等不属于站点的内容，并把 `deploy/_headers`、`deploy/404.html` 复制到输出根目录。

当前输出：**88 个文件，23.5 MB**。

---

## 二、方式 A：直接上传（最快，不需要 Git）

1. 打开 Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → **Upload assets**
2. 项目名随便起，例如 `portfolio`，部署后会得到 `portfolio.pages.dev`
3. 把 `public/` 整个文件夹拖进去，或者用命令行：

```bash
npx wrangler pages deploy public --project-name=portfolio
```

4. 之后每次更新，重新跑 `build.py` 再上传一次即可。

---

## 三、方式 B：连接 Git 仓库（推送即部署）

1. 先确认 `public/` **已经提交进仓库**（Git 集成只能看到仓库里的文件）
2. Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
3. 选仓库，然后填：
   - **Build command**：留空
   - **Build output directory**：`public`
4. 之后每次 push 会自动重新部署。

## 五、新增的两个文件

**`_headers`** —— Cloudflare Pages 会自动识别。作用是给静态资源加缓存头，并补上几个安全响应头（`nosniff`、`Referrer-Policy`、`X-Frame-Options`、`Permissions-Policy`）。

**`404.html`** —— Cloudflare Pages 找不到页面时会自动返回它，沿用站点的 `#348cb2` 主色，无需额外配置。

## 六、注意事项

- **不要上传 `.git`**。它在本目录里有 21 MB，构建脚本已经排除。如果绕过脚本直接传整个文件夹，这些历史记录会一并公开。
- **免费版每月 500 次部署**，个人站点足够用。
- 绑定自定义域名：Pages 项目 → **Custom domains** → 添加域名，Cloudflare 会自动配好 CNAME（域名不在 Cloudflare 托管时，需要去你的 DNS 服务商手动加一条 CNAME 指向 `xxx.pages.dev`）。
- 当前 Git 远程是 `https://github.com/zyy051206/-.git`，仓库名就叫 `-`。走 Git 集成的话，Pages 项目名会沿用这个，建议先在 GitHub 上把仓库改个正常名字。
- `public/` 是生成物。如果你更希望仓库里只存源文件，可以在 `.gitignore` 里加一行 `public/`，然后只用方式 A 部署。
